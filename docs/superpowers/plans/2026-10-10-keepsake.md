# Keepsake Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a private local Keepsake product that lets a sender make an intimate, accessible photo-and-letter gift and lets a recipient experience its envelope-to-memory journey.

**Architecture:** A Vite React TypeScript client owns the sender studio, recipient interaction state machine, WebGL heart scene, and DOM fallback. A compact Express + SQLite service persists gift records and private local image binaries, validates tokenized recipient access, and exposes separate management actions. The client uses a reducer plus a generation-scoped transition scheduler so physical envelope animation cannot be corrupted by repeated interaction or stale timers.

**Tech Stack:** React 18, TypeScript, Vite, Express, SQLite, Multer, Sharp, Three.js/react-three-fiber, Vitest, Playwright, ESLint, Prettier.

**Spec:** `docs/superpowers/specs/2026-10-10-keepsake-design.md`

## Global Constraints

- Do not reuse source, wording, artwork, hierarchy, styles, or animation code from any existing repository.
- Primary UI is dark, warm-nostalgic, responsive, semantic, keyboard/touch/mouse accessible, and reduced-motion aware.
- Gift creation accepts exactly 1–12 validated images; sender preview is required before a share token is made.
- Recipient links contain only opaque high-entropy tokens; management tokens never appear in recipient URLs.
- The guarded interaction sequence is arrival → closed → opening → flap-open → letter-revealed → extracting → reading → memories → reset/dismissed.
- Maintain credible envelope layer order in code: rear body, letter, flap, front pocket, seal, controls; no closed-state letter leakage.
- Use the native DOM memory scene when WebGL is absent or performance mode is enabled.
- Do not deploy, publish, create accounts, push, or use external secrets.

## Review Focus

- Long Vietnamese names and long letters must wrap within the invitation and reading surfaces without clipping; cover in responsive Playwright snapshots in Task 7.
- Corrupt, non-image, oversize, and thirteenth uploads must fail before storage with clear sender errors; cover in Task 3 unit/API tests and Task 8 browser tests.
- Rapid mixed pointer, keyboard, and focus/resize input must not skip or regress envelope states; cover reducer/scheduler tests in Task 4 and E2E in Task 8.
- Expired, revoked, deleted, unknown, offline, and slow recipient loads must reveal no private metadata and must provide a coherent recovery state; cover API tests in Task 2 and browser route interception in Task 8.
- Mixed portrait, landscape, and square media must remain discoverable and undistorted in both WebGL and fallback memory scenes; cover visual browser tests in Task 8.
